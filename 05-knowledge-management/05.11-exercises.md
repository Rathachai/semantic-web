### Exercise 1: ออกแบบ TBox ของโรงพยาบาล

**โจทย์**

สร้างไฟล์ `hospital-tbox.ttl` ที่มี **primitive class** และ **defined class** ตามข้อกำหนด

**Primitive classes ที่ต้องมี (อย่างน้อย 15)**

```
Agent
├── Person
│   ├── Patient
│   └── Staff
│       ├── Doctor
│       │   ├── Surgeon
│       │   └── Physician
│       └── Nurse
└── Organization
    ├── Hospital
    └── Department
        ├── EmergencyDepartment
        └── SurgicalDepartment

Condition
├── Disease
│   ├── InfectiousDisease
│   └── ChronicDisease
└── Symptom

Treatment
├── Medication
├── Surgery
└── Therapy

Appointment
```

**Defined classes ที่ต้องมี (อย่างน้อย 5)**

| Class | นิยาม |
| --- | --- |
| `CriticalPatient` | Patient ที่มี `hasCondition` ไปยัง Condition ที่ `severity` = "critical" |
| `SurgicalPatient` | Patient ที่ได้รับ `receivesTreatment` ไปยัง Surgery อย่างน้อยหนึ่ง |
| `MultiConditionPatient` | Patient ที่มี `hasCondition` อย่างน้อย 3 Condition |
| `BusyDoctor` | Doctor ที่ `treats` ผู้ป่วยอย่างน้อย 10 คน |
| `Specialist` | Doctor ที่ `specializesIn` Disease อย่างน้อยหนึ่ง |

**Disjointness ที่ต้องมี**

- `Patient` กับ `Staff` disjoint
- `Doctor`, `Nurse` disjoint
- `Disease` กับ `Symptom` disjoint
- `Medication`, `Surgery`, `Therapy` — ใช้ `owl:AllDisjointClasses`

**ข้อกำหนดเพิ่มเติม**

- ทุก class มี `rdfs:label`@en และ `rdfs:comment`@en
- ontology header มี `dcterms:title`, `owl:versionInfo`, `owl:versionIRI`

**Expected output**

```bash
python -c "
from rdflib import Graph
from rdflib.namespace import OWL, RDF, RDFS
g = Graph().parse('hospital-tbox.ttl', format='turtle')
classes = set(g.subjects(RDF.type, OWL.Class))
defined = {c for c in classes if list(g.objects(c, OWL.equivalentClass))}
no_label = [c for c in classes if not list(g.objects(c, RDFS.label))]
print(f'triples      : {len(g)}')
print(f'classes      : {len(classes)}')
print(f'  primitive  : {len(classes - defined)}')
print(f'  defined    : {len(defined)}')
print(f'disjointWith : {len(list(g.subject_objects(OWL.disjointWith)))}')
print(f'ขาด label    : {len(no_label)}')
assert len(classes) >= 20 and len(defined) >= 5 and not no_label
print('PASS')
"
```

```
triples      : 214
classes      : 21
  primitive  : 16
  defined    : 5
disjointWith : 3
ขาด label    : 0
PASS
```

### Exercise 2: ออกแบบ RBox

**โจทย์**

สร้างไฟล์ `hospital-rbox.ttl` ที่มี property axiom ตามข้อกำหนด

**Object properties (อย่างน้อย 12)**

| Property | Domain | Range | Characteristics |
| --- | --- | --- | --- |
| `hasCondition` | Patient | Condition | — |
| `hasSymptom` | Condition | Symptom | — |
| `treats` | Doctor | Patient | — |
| `treatedBy` | Patient | Doctor | inverse ของ `treats` |
| `receivesTreatment` | Patient | Treatment | — |
| `prescribes` | Doctor | Medication | — |
| `worksIn` | Staff | Department | — |
| `partOf` | Organization | Organization | **Transitive** |
| `hasPrimaryDoctor` | Patient | Doctor | **Functional** |
| `colleagueOf` | Staff | Staff | **Symmetric, Irreflexive** |
| `specializesIn` | Doctor | Disease | — |
| `contraindicates` | Medication | Condition | — |

**Role hierarchy ที่ต้องมี**

```
careProvidedBy
├── treats
└── nursedBy
```

**Role chains ที่ต้องมี (อย่างน้อย 2)**

| Chain | ความหมาย |
| --- | --- |
| `worksIn ∘ partOf ⊑ worksInHospital` | ทำงานในแผนกที่อยู่ในโรงพยาบาล = ทำงานในโรงพยาบาลนั้น |
| `treats ∘ hasCondition ⊑ treatsCondition` | หมอที่รักษาคนไข้ที่มีโรค = รักษาโรคนั้น |

**Data properties (อย่างน้อย 6)**

`patientId` (InverseFunctional), `staffId` (InverseFunctional), `admissionDate` (`xsd:dateTime`),
`severity` (`xsd:string`), `dosageMg` (`xsd:decimal`), `bedNumber` (`xsd:integer`)

**คำถามที่ต้องตอบพร้อมส่ง**

1. ทำไม `partOf` ที่เป็น transitive จึงใช้ใน cardinality restriction ไม่ได้
2. `hasPrimaryDoctor` ที่เป็น functional จะทำให้เกิดอะไรขึ้นถ้ามีการประกาศสองค่า
3. role chain ทั้งสองข้อผ่าน regularity condition หรือไม่ อธิบาย

**Expected output**

```
object properties     : 14
  transitive          : 1  ['partOf']
  functional          : 1  ['hasPrimaryDoctor']
  symmetric           : 1  ['colleagueOf']
  inverse pairs       : 1  [('treats','treatedBy')]
  property chains     : 2  ['worksInHospital', 'treatsCondition']
data properties       : 6
  inverse functional  : 2  ['patientId', 'staffId']
```

### Exercise 3: สร้าง ABox และทำนายผล reasoning

**โจทย์**

สร้างไฟล์ `hospital-abox.ttl` ที่มี:

- **ผู้ป่วย 6 คน** — คนหนึ่งมี 3 condition, คนหนึ่งได้รับ surgery, คนหนึ่งไม่มี condition เลย
- **หมอ 3 คน** — คนหนึ่งรักษาผู้ป่วย 10+ คน, คนหนึ่ง specialize ในโรค
- **พยาบาล 2 คน**
- **แผนก 3 แผนก** ที่ `partOf` โรงพยาบาลเดียวกัน
- **โรค 5 โรค**, **การรักษา 4 อย่าง**
- `owl:AllDifferent` สำหรับ individual ทุกกลุ่ม
- `owl:imports` ชี้ไปที่ TBox และ RBox

**ก่อนรัน reasoner** เขียนไฟล์ `prediction.md` ทำนาย:

| ต้องทำนาย | รูปแบบคำตอบ |
| --- | --- |
| ผู้ป่วยคนไหนจะเป็น `CriticalPatient` | รายชื่อ + เหตุผล |
| ผู้ป่วยคนไหนจะเป็น `MultiConditionPatient` | รายชื่อ + บอกว่าต้องมี AllDifferent หรือไม่ |
| หมอคนไหนจะเป็น `BusyDoctor` / `Specialist` | รายชื่อ + เหตุผล |
| `worksInHospital` จะถูกอนุมานให้ใครบ้าง | รายชื่อ + trace ผ่าน role chain |
| ผู้ป่วยที่ไม่มี condition จะถูกจัดเป็นอะไร | อธิบายด้วยหลัก OWA |

**Expected output**

```
====================================================================
  คำทำนาย vs ผลจริง
====================================================================
  CriticalPatient        ทำนาย: ['patient001']            ได้จริง: ['patient001']            ✅
  MultiConditionPatient  ทำนาย: ['patient002']            ได้จริง: []                        ❌
  SurgicalPatient        ทำนาย: ['patient003']            ได้จริง: ['patient003']            ✅
  BusyDoctor             ทำนาย: ['drAdams']               ได้จริง: ['drAdams']               ✅
  Specialist             ทำนาย: ['drBrown']               ได้จริง: ['drBrown']               ✅

  สาเหตุที่ MultiConditionPatient ไม่ตรง:
    ลืมประกาศ owl:AllDifferent ให้ condition ทั้ง 3 ตัว
    reasoner จึงไม่รู้ว่าเป็นคนละโรค -> cardinality ≥3 ไม่ทำงาน

  หลังเพิ่ม AllDifferent:
  MultiConditionPatient  ได้จริง: ['patient002']  ✅
```

### Exercise 4: ตรวจจับและแก้ inconsistency

**โจทย์**

เพิ่มข้อมูลต่อไปนี้เข้า ABox ทีละชุด แล้วรัน reasoner หลังแต่ละชุด

| ชุด | ข้อมูลที่เพิ่ม | คาดว่าเกิดอะไร |
| --- | --- | --- |
| A | `hosp:drAdams a hosp:Patient .` | ? |
| B | `hosp:patient001 hosp:hasPrimaryDoctor hosp:drAdams , hosp:drBrown .` | ? |
| C | `hosp:nurse01 hosp:colleagueOf hosp:nurse01 .` | ? |
| D | `hosp:dept01 hosp:partOf hosp:dept01 .` | ? |

**สำหรับแต่ละชุดให้**

1. ทำนายก่อนว่าจะ inconsistent หรือไม่ และเพราะอะไร
2. รัน reasoner ตรวจสอบ
3. เขียน **justification** — axiom ชุดที่เล็กที่สุดที่ทำให้เกิดปัญหา
4. เสนอทางแก้

**Expected output**

```
====================================================================
  ชุด A: drAdams เป็นทั้ง Doctor และ Patient
====================================================================
  ทำนาย : INCONSISTENT
  ผลจริง : ❌ INCONSISTENT
  Justification:
    1. hosp:Patient owl:disjointWith hosp:Staff
    2. hosp:Doctor rdfs:subClassOf hosp:Staff
    3. hosp:drAdams a hosp:Doctor
    4. hosp:drAdams a hosp:Patient
  ทางแก้: ลบข้อ 4 หรือถอด disjointness ถ้าโดเมนอนุญาตให้พนักงานเป็นคนไข้ได้

====================================================================
  ชุด B: patient001 มี primary doctor 2 คน
====================================================================
  ทำนาย : ไม่ inconsistent แต่ reasoner จะสรุปว่า drAdams sameAs drBrown
  ผลจริง : ✅ consistent, และ hosp:drAdams owl:sameAs hosp:drBrown
  Justification:
    1. hosp:hasPrimaryDoctor a owl:FunctionalProperty
    2. patient001 hasPrimaryDoctor drAdams
    3. patient001 hasPrimaryDoctor drBrown
    → functional บังคับให้มีค่าเดียว ⇒ ทั้งสองต้องเป็นคนเดียวกัน
  ทางแก้: เพิ่ม owl:AllDifferent ให้หมอทุกคน แล้วจะกลายเป็น INCONSISTENT
          ซึ่งเป็นสิ่งที่ต้องการ (จับข้อมูลผิดได้)

====================================================================
  ชุด C: nurse01 colleagueOf ตัวเอง
====================================================================
  ทำนาย : INCONSISTENT (colleagueOf เป็น IrreflexiveProperty)
  ...
```

### Exercise 5: Modularize และวาง versioning

**โจทย์**

1. **แยก** ontology จาก Exercise 1–3 ออกเป็น module ตามโครงสร้างนี้

```
onto/
├── hospital-core.ttl        ← Person, Organization, Condition, Treatment (primitive)
├── hospital-roles.ttl       ← RBox ทั้งหมด
├── hospital-clinical.ttl    ← Disease, Symptom, defined class ทางคลินิก
├── hospital-admin.ttl       ← Appointment, Department, defined class ทางบริหาร
└── hospital.ttl             ← owl:imports ทั้งสี่
data/
└── hospital-abox.ttl
catalog-v001.xml
```

2. ทุก module มี `owl:versionInfo` และ `owl:versionIRI` ของตัวเอง
3. เขียน **catalog file** ให้ resolve IRI เป็นไฟล์ local
4. ทำสถานการณ์ **deprecation**: เปลี่ยนชื่อ `hosp:sickness` เป็น `hosp:condition`
   โดยไม่ทำให้ข้อมูลเก่าพัง
5. เขียนสคริปต์ `check_kb.py` ที่ทำ CI 5 ขั้น:
   syntax → annotation ครบ → consistency → competency question → SHACL

**Competency question ที่ต้องผ่าน (อย่างน้อย 5)**

## เกณฑ์ตรวจ

| Exercise | ผ่านเมื่อ |
| --- | --- |
| 1 | ≥ 20 class, ≥ 5 defined class, ≥ 3 disjointness, ไม่มี term ขาด annotation |
| 2 | ครบทุก characteristic ที่ระบุ, role chain 2 ตัวทำงาน, ตอบคำถาม 3 ข้อได้ |
| 3 | ทำนายถูก ≥ 80% และอธิบายส่วนที่พลาดด้วยหลัก No-UNA/OWA ได้ |
| 4 | ระบุ justification ครบทั้ง 4 ชุด และเสนอทางแก้ที่สมเหตุสมผล |
| 5 | module import ไปทางเดียว, มี catalog file, CI ทั้ง 5 ขั้นผ่าน |

## Key Points

- Exercise 1–2 ฝึกออกแบบ **TBox และ RBox แยกกัน** ซึ่งเป็นโครงสร้างที่ ontology จริงใช้
- Exercise 3 ฝึก **ทำนายผล reasoning ก่อนรัน** — และมักพลาดที่ `owl:AllDifferent` ซึ่งเป็นบทเรียนสำคัญ
- Exercise 4 ครอบคลุมกลไก 4 แบบที่ทำให้ KB inconsistent: **disjointness, functional, irreflexive, asymmetric**
- **Functional property + AllDifferent** เป็นคู่ที่ทรงพลังในการจับข้อมูลผิดพลาดโดยอัตโนมัติ
- Exercise 5 ฝึก **modularization, versioning, deprecation และ CI** ซึ่งเป็นงานวิศวกรรมจริงของ ontology
- เก็บ ontology จาก Exercise ทั้งหมดไว้ เพราะจะถูกนำไปใช้ต่อใน [Chapter 10](../10-ontology-design/10.12-exercises.md) และ [Chapter 11](../11-swrl/11.12-exercises.md)
