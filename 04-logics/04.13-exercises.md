### Exercise 1: แปล 5 ประโยคเป็น FOL แล้วเป็น DL

**โจทย์**

แปลประโยคภาษาอังกฤษต่อไปนี้เป็น **FOL** แล้วเป็น **DL** แล้วเขียนเป็น **OWL (Turtle shorthand)**

1. *"Every graduate student is a student who is enrolled in at least one graduate course."*
2. *"No course is both an undergraduate course and a graduate course."*
3. *"A full professor is a professor who supervises at least three graduate students."*
4. *"Every course is taught by exactly one professor."*
5. *"A department head is a person who heads a department and is a member of that department."*

**สำหรับแต่ละข้อให้ระบุด้วยว่า**

- ใช้ `⊑` หรือ `≡` และเพราะอะไร
- ต้องใช้ constructor ตัวไหนบ้าง (`⊓ ⊔ ¬ ∃ ∀ ≥ ≤ =`)
- ต้องใช้ DL family อะไรเป็นอย่างน้อย

**Expected output**

ตารางรูปแบบนี้:

| # | FOL | DL | OWL construct | DL family ต่ำสุด |
| --- | --- | --- | --- | --- |
| 1 | `∀x (GradStudent(x) ↔ Student(x) ∧ ∃y(GradCourse(y) ∧ enrolledIn(x,y)))` | `GradStudent ≡ Student ⊓ ∃enrolledIn.GradCourse` | `owl:equivalentClass`, `owl:someValuesFrom` | `ALC` |
| 2 | `∀x ¬(UGCourse(x) ∧ GradCourse(x))` | `UGCourse ⊓ GradCourse ⊑ ⊥` | `owl:disjointWith` | `ALC` |
| 3 | … | `FullProfessor ≡ Professor ⊓ (≥3 supervises.GradStudent)` | `owl:minQualifiedCardinality` | `ALCQ` |
| … | | | | |

> ⚠️ **ข้อ 5 มีกับดัก** — วลี "that department" หมายถึง department **ตัวเดียวกัน** ในทั้งสองความสัมพันธ์
> ซึ่งเป็น **variable co-occurrence** ที่ DL แสดงไม่ได้ ให้อธิบายว่าทำไม และเสนอทางออก (SWRL)

พร้อมไฟล์ `answer-01.ttl` ที่ parse ผ่าน:

```bash
python -c "from rdflib import Graph; g=Graph(); g.parse('answer-01.ttl',format='turtle'); print(len(g),'triples')"
```

### Exercise 2: ระบุ DL family ของ ontology ที่ให้มา

**โจทย์**

พิจารณา ontology ต่อไปนี้

```turtle
@prefix ex:   <http://example.org/> .
@prefix owl:  <http://www.w3.org/2002/07/owl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .

ex:Person       a owl:Class .
ex:Student      rdfs:subClassOf ex:Person .
ex:Professor    rdfs:subClassOf ex:Person .
ex:Student      owl:disjointWith ex:Professor .

ex:hasSupervisor a owl:ObjectProperty ;
    owl:inverseOf ex:supervises .

ex:hasAncestor a owl:TransitiveProperty .

ex:hasParent rdfs:subPropertyOf ex:hasAncestor .

ex:Weekday owl:equivalentClass [
    a owl:Class ;
    owl:oneOf ( ex:mon ex:tue ex:wed ex:thu ex:fri )
] .

ex:BusyProfessor owl:equivalentClass [
    a owl:Class ;
    owl:intersectionOf (
        ex:Professor
        [ a owl:Restriction ;
          owl:onProperty ex:supervises ;
          owl:minCardinality "5"^^xsd:nonNegativeInteger ]
    )
] .

ex:age a owl:DatatypeProperty ;
    rdfs:range xsd:integer .
```

**ให้ทำ**

1. ระบุ **ทุก constructor** ที่ ontology นี้ใช้ พร้อมชี้บรรทัดที่พบ
2. สรุปว่าเป็น DL family ตัวไหน (แสดงการไล่ตัวอักษรทีละตัว)
3. ระบุว่าตรงกับ **OWL species** ไหน
4. บอก **complexity class** ของ satisfiability
5. ถ้าเปลี่ยน `owl:minCardinality` เป็น `owl:minQualifiedCardinality` + `owl:onClass` จะเปลี่ยน DL family เป็นอะไร
6. ถ้าเอา `owl:oneOf` ออก จะเปลี่ยนเป็นอะไร และ complexity ดีขึ้นแค่ไหน

**Expected output**

```
Constructors ที่พบ:
  - owl:disjointWith          -> ต้องมี ¬   (ALC)
  - owl:TransitiveProperty    -> S
  - rdfs:subPropertyOf        -> H
  - owl:oneOf                 -> O
  - owl:inverseOf             -> I
  - owl:minCardinality        -> N
  - owl:DatatypeProperty      -> (D)

สรุป: SHOIN(D)
OWL species: OWL 1 DL
Complexity: NExpTime-complete

ข้อ 5: minQualifiedCardinality -> N กลายเป็น Q -> SHOIQ(D) = subset ของ OWL 2 DL
ข้อ 6: เอา oneOf ออก -> SHIN(D), complexity ลดจาก NExpTime เป็น ExpTime
```

### Exercise 3: สร้าง KB แล้วรัน reasoner ยืนยันคำตอบ

**โจทย์**

จาก DL axiom ต่อไปนี้

```
--- TBox ---
Person          ⊑ ⊤
Student         ⊑ Person
Professor       ⊑ Person
Student ⊓ Professor ⊑ ⊥
Course          ⊑ ⊤
GraduateCourse  ⊑ Course
GraduateStudent ≡ Student ⊓ ∃enrolledIn.GraduateCourse
BusyProfessor   ≡ Professor ⊓ (≥ 2 teaches.Course)
LazyStudent     ≡ Student ⊓ ¬∃enrolledIn.Course

--- ABox ---
alice : Student ,  (alice, ai501) : enrolledIn ,  ai501 : GraduateCourse
bob   : Student
prof1 : Professor , (prof1, cs101) : teaches , (prof1, ai501) : teaches
prof2 : Professor , (prof2, cs101) : teaches
cs101 : Course
```

1. เขียนเป็น `code` ด้วย owlready2 ในไฟล์ `exercise3.py`
2. **ก่อนรัน reasoner** ให้ทำนายว่า:
   - `alice` จะได้ type อะไรเพิ่ม
   - `bob` จะได้ type อะไรเพิ่ม (ระวัง OWA!)
   - `prof1` และ `prof2` จะได้อะไร
   - มี class ไหน unsatisfiable หรือไม่
3. รัน HermiT แล้วเทียบผล
4. อธิบายผลของ `bob` ให้ละเอียด — ทำไมจึงไม่ถูกจัดเป็น `LazyStudent` ทั้งที่ไม่มี `enrolledIn` เลย

**Expected output**

```
====================================================================
  คำทำนาย vs ผลจริง
====================================================================
  alice   ทำนาย: [GraduateStudent]        ได้จริง: [GraduateStudent]        ✅
  bob     ทำนาย: [Student]                ได้จริง: [Student]                ✅
  prof1   ทำนาย: [BusyProfessor]          ได้จริง: [BusyProfessor]          ✅
  prof2   ทำนาย: [Professor]              ได้จริง: [Professor]              ✅

  unsatisfiable classes: []

====================================================================
  อธิบายผลของ bob
====================================================================
  bob ไม่ถูกจัดเป็น LazyStudent เพราะ Open World Assumption:
  การที่ ABox ไม่มี triple (bob, ?, enrolledIn) ไม่ได้แปลว่า bob ไม่ได้ลงเรียนอะไร
  แปลว่า "ไม่ทราบ" เท่านั้น reasoner จึงสรุปว่า bob : ¬∃enrolledIn.Course ไม่ได้

  ถ้าอยากให้สรุปได้ ต้องเพิ่ม:
      bob : ≤0 enrolledIn.Course        (closure axiom)
  หรือใช้ SHACL ซึ่งทำงานแบบ closed world
```

จากนั้นเพิ่ม closure axiom แล้วรันซ้ำ ต้องได้ `bob : LazyStudent`

### Exercise 4: หาสาเหตุของ inconsistency

**โจทย์**

KB ต่อไปนี้ **inconsistent** ให้หาสาเหตุ

```
--- TBox ---
Vegetarian ≡ Person ⊓ ∀eats.¬Meat
Carnivore  ≡ Person ⊓ ∃eats.Meat
Beef       ⊑ Meat
Tofu       ⊑ ¬Meat
Vegetarian ⊓ Carnivore ⊑ ⊥

--- ABox ---
alice : Person
alice : Vegetarian
(alice, beefSteak) : eats
beefSteak : Beef
```

1. เขียน **justification** — เซตของ axiom ที่เล็กที่สุดที่ทำให้เกิด inconsistency
2. เสนอ **ทางแก้ 3 แบบ** พร้อมข้อดีข้อเสีย:
   - แก้ ABox
   - แก้ TBox
   - แก้นิยาม
3. implement ด้วย owlready2 แล้วยืนยันว่า reasoner รายงาน inconsistency จริง
4. แก้แล้วยืนยันว่า consistent

**Expected output**

```
====================================================================
  Justification
====================================================================
  1. Vegetarian ≡ Person ⊓ ∀eats.¬Meat
  2. Beef ⊑ Meat
  3. alice : Vegetarian
  4. (alice, beefSteak) : eats
  5. beefSteak : Beef

  Derivation:
    (3) + (1)  →  alice : ∀eats.¬Meat
    (4) + above →  beefSteak : ¬Meat
    (5) + (2)   →  beefSteak : Meat
    ขัดกัน: beefSteak : Meat ⊓ ¬Meat  →  ⊥

====================================================================
  ผลการรัน
====================================================================
  ก่อนแก้ : ❌ OwlReadyInconsistentOntologyError
  หลังแก้ (ลบ alice:Vegetarian) : ✅ consistent
                                   และ reasoner อนุมานว่า alice : Carnivore
```

### Exercise 5: เปรียบเทียบ reasoner และวัดเวลา

**โจทย์**

1. สร้าง ontology ที่มี:
   - class hierarchy ลึก 5 ชั้น กว้าง 10 (รวม ~50 class)
   - defined class 10 ตัวที่ใช้ `∃r.C` และ `⊓`
   - individual 100 ตัว
2. รัน reasoning ด้วย **HermiT** และ **Pellet** วัดเวลา
3. สร้าง **เวอร์ชัน OWL 2 EL** ของ ontology เดียวกัน (ถอด `¬`, `⊔`, `∀`, cardinality ออก)
   แล้วรันด้วย **ELK** (ผ่าน Protégé หรือ owlready2)
4. เพิ่ม `owl:oneOf` และ `owl:inverseOf` เข้าไป แล้ววัดเวลาใหม่
5. สรุปเป็นตารางและกราฟ

**Expected output**

```
====================================================================
  Benchmark
====================================================================
  Ontology            Classes  Individuals  Reasoner   Time (s)
  ------------------------------------------------------------
  base (ALC)              50          100   HermiT        0.42
  base (ALC)              50          100   Pellet        0.61
  EL version              50          100   ELK           0.08
  + nominal (O)           50          100   HermiT        1.87
  + nominal + inverse     50          100   HermiT        4.23

  ข้อสรุป:
  - ELK เร็วกว่า HermiT ประมาณ 5 เท่าบน ontology เดียวกันที่ตัดให้อยู่ใน EL
  - การเพิ่ม nominal ทำให้ช้าลง ~4.5 เท่า
  - การเพิ่ม inverse ซ้อนเข้าไปอีก ทำให้ช้าลงรวม ~10 เท่า
```

พร้อมย่อหน้าอธิบายว่า **ทำไม nominal จึงแพง** (อ้าง [04.07](04.07-dl-family.md))

## Key Points

- Exercise 1 ฝึกทักษะแกนของ ontology engineering: **แปลความต้องการเป็น axiom ที่แม่นยำ**
- ความต่างระหว่าง **`⊑` (necessary)** กับ **`≡` (necessary + sufficient)** เป็นสิ่งที่ต้องตัดสินใจทุกครั้งที่สร้าง class
- Exercise 2 ฝึกอ่าน ontology แล้วบอก **DL family** ได้ — จำเป็นตอนประเมินว่า reasoner ตัวไหนเหมาะ
- Exercise 3 ตอกย้ำผลของ **Open World Assumption** ต่อ negative class เช่น `LazyStudent`
- **Closure axiom** (`≤0 r.C`) คือวิธีจำลอง closed world ใน OWL เมื่อจำเป็น
- Exercise 4 ฝึกอ่าน **justification** ซึ่งเป็นทักษะ debug ontology ที่สำคัญที่สุด
- Exercise 5 ทำให้เห็นด้วยตัวเลขจริงว่า **nominal และ inverse แพงแค่ไหน** และทำไมการอยู่ใน OWL 2 EL จึงคุ้ม
- เก็บ ontology จาก Exercise 3 ไว้ เพราะจะถูกนำไปขยายใน [Chapter 05](../05-knowledge-management/05.09-python-kb.md)
