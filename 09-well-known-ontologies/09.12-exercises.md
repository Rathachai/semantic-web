# 09.12 แบบฝึกหัด Chapter 09

แบบฝึกหัดชุดนี้ให้ **map โดเมนจริงเข้ากับ ontology ที่มีอยู่** แล้วอธิบายเหตุผลของทุกการตัดสินใจ

### Exercise 2: ค้นหาและประเมิน vocabulary

**โจทย์**

สำหรับ **concept และ relation ทุกตัวใน glossary** ให้ค้นหา vocabulary ที่มีอยู่แล้ว

**ต้องค้นจากอย่างน้อย 3 แหล่ง**

- `schema.org`
- LOV (`lov.linkeddata.es`)
- BioPortal / AgroPortal / OBO Foundry (ถ้าเกี่ยวข้อง)

**สำหรับ vocabulary ที่พบ ให้ประเมินตามเกณฑ์ 7 ข้อ**

| เกณฑ์ | วิธีตรวจ |
| --- | --- |
| License | หา `dcterms:license` |
| Maintenance | `owl:versionInfo`, `dcterms:modified` |
| Adoption | LOV แสดงจำนวน dataset |
| Documentation | `rdfs:label`/`rdfs:comment` coverage |
| Dereferenceable | `curl -H "Accept: text/turtle" <IRI>` |
| Stability | IRI เปลี่ยนบ่อยไหม |
| OWL Profile | อยู่ใน EL/QL/RL ไหม |

### Exercise 3: สร้าง Mapping Table

**โจทย์**

สร้างตาราง mapping **ทุก concept และ relation** ในโดเมนของคุณ

**สำหรับแต่ละรายการต้องระบุ**

1. Term ที่เลือกใช้
2. **การตัดสินใจ**: reuse ตรง / extend / สร้างใหม่ + เชื่อม
3. **Alignment property** ที่ใช้ และ **เหตุผล**
4. ทางเลือกอื่นที่พิจารณาแล้วไม่เลือก และ**ทำไม**

**Expected output**

```markdown
## Class Mapping

| Concept ของเรา | Term ที่เลือก | การตัดสินใจ | Alignment | เหตุผล |
|---|---|---|---|---|
| Paper | `fabio:ConferencePaper` | reuse ตรง | — | ความหมายตรงทุกประการ |
| Author | `foaf:Person` | reuse ตรง | — | ผู้เขียนคือคน |
| Reviewer | `conf:Reviewer` | สร้างใหม่ | `rdfs:subClassOf foaf:Person` | reviewer เป็นบทบาท ไม่ใช่ชนิดของคน — แต่ FOAF ไม่มี role model |
| Session | `conf:Session` | สร้างใหม่ + เชื่อม | `skos:closeMatch schema:Event` | schema:Event กว้างเกินไป ไม่ผูกกับ conference |
| Conference | `schema:Event` | extend | `rdfs:subClassOf` | conference เป็น event ประเภทหนึ่ง |

**ทางเลือกที่พิจารณาแล้วไม่เลือก**

| Term | ทำไมไม่เลือก |
|---|---|
| `swrc:InProceedings` | vocabulary ไม่ maintain ตั้งแต่ 2005, dereference ไม่ได้ |
| `bibo:Article` | ไม่แยก conference paper ออกจาก journal article |
| `schema:ScholarlyArticle` | ไม่มี property สำหรับ session/track |

## Property Mapping

| Relation ของเรา | Term ที่เลือก | Alignment | เหตุผล |
|---|---|---|---|
| authoredBy | `dcterms:creator` | reuse ตรง | range เป็น Agent ตรงกับที่ต้องการ |
| reviewedBy | `conf:reviewedBy` | `rdfs:subPropertyOf dcterms:contributor` | ไม่มี term มาตรฐาน แต่ reviewer เป็นผู้มีส่วนร่วม |
| presentedIn | `conf:presentedIn` | `rdfs:subPropertyOf schema:subEvent` (inverse) | — |
| cites | `cito:cites` | reuse ตรง | CiTO ออกแบบมาเพื่อสิ่งนี้โดยเฉพาะ |
```

### Exercise 4: เขียน Ontology และตรวจการ Reuse

**โจทย์**

1. เขียนไฟล์ `<domain>.ttl` ตาม mapping table
2. **reuse ratio ต้อง ≥ 60%** — วัดจากจำนวน predicate ที่มาจาก vocabulary มาตรฐาน
3. ทุก term ที่สร้างเองต้องมี:
   - `rdfs:label`@en
   - `rdfs:comment`@en ที่อธิบาย**ขอบเขต**และ**ทำไมไม่ reuse**
   - alignment กลับไปยัง vocabulary มาตรฐาน

### Exercise 5: เชื่อมกับ Wikidata และ DBpedia

**โจทย์**

1. หา **entity ในโดเมนของคุณที่น่าจะมีใน Wikidata** (องค์กร สถานที่ คน ที่มีชื่อเสียง)
2. เขียนสคริปต์ที่:
   - ดึงชื่อ entity จาก graph ของคุณ
   - ค้นหาใน Wikidata ด้วย **`VALUES` + chunking** (ไม่ยิงทีละตัว)
   - จัดการ **ambiguous match** (พบมากกว่า 1)
   - สร้าง link ด้วย property ที่เหมาะสมกับระดับความมั่นใจ
3. ดึงข้อมูลเพิ่มจาก Wikidata (พิกัด เว็บไซต์ วันก่อตั้ง รูปภาพ)
4. เชื่อมกับ DBpedia ด้วย `owl:sameAs` ที่มีอยู่ใน Wikidata

**กฎการเลือก alignment property**

| สถานการณ์ | ใช้ |
| --- | --- |
| พบ 1 รายการ + มี identifier ยืนยัน | `owl:sameAs` |
| พบ 1 รายการ แต่ match จากชื่อเท่านั้น | `skos:closeMatch` |
| พบมากกว่า 1 | `rdfs:seeAlso` ทุกตัว + บันทึกไว้ให้คนตรวจ |
| ไม่พบ | ไม่ทำอะไร |

**Expected output**

```
====================================================================
  ENTITY LINKING กับ WIKIDATA
====================================================================
  entity ที่ต้อง link : 24
  chunk size         : 25
  HTTP requests      : 1        ← ไม่ใช่ 24!
  เวลา               : 3.2 วินาที

  ผลการ match:
    ✅ owl:sameAs      : 18  (พบ 1 รายการ + มี identifier)
    ⚠️ skos:closeMatch : 4   (พบ 1 รายการ จากชื่อเท่านั้น)
    ⚠️ rdfs:seeAlso    : 1   (ambiguous — พบ 2 รายการ)
    ❌ ไม่พบ           : 1

  Ambiguous case ที่ต้องให้คนตรวจ:
    "Cambridge" → wd:Q350 (Cambridge, UK)
                → wd:Q49111 (Cambridge, Massachusetts)

  ข้อมูลที่ดึงมาเสริม:
    coordinates (P625)   : 18
    official website     : 15
    inception (P571)     : 12
    image (P18)          :  9
    DBpedia sameAs       : 16

  เพิ่ม 94 triples เข้า graph
```

พร้อมย่อหน้าอธิบาย 3–5 บรรทัดว่า **ทำไมจึงไม่ควรใช้ `owl:sameAs` กับ ambiguous match**
(อ้าง [05.05](../05-knowledge-management/05.05-abox-negation.md) เรื่อง sameAs explosion)

### Exercise 6: Validate และเขียน Documentation

**โจทย์**

1. เขียน **SHACL shape** ตรวจ ontology ของคุณ อย่างน้อย 5 constraint:

```turtle
@prefix sh:   <http://www.w3.org/ns/shacl#> .
@prefix owl:  <http://www.w3.org/2002/07/owl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

# 1) ทุก class ต้องมี label
# 2) ทุก class ที่สร้างเองต้องมี comment
# 3) ทุก class ที่สร้างเองต้องมี alignment
# 4) ทุก property ต้องมี domain และ range
# 5) ontology header ต้องครบ
```

2. รัน **`pyshacl`** แล้วแก้จนผ่าน
3. รัน **reasoner** ตรวจ consistency
4. สร้าง **HTML documentation** ด้วย `pylode` หรือ Widoco

```bash
pip install pylode
pylode -i conference.ttl -o docs/index.html
```

5. แปลง competency question เป็น **SPARQL** แล้วทดสอบว่าตอบได้ทุกข้อ

**Expected output**

## เกณฑ์ตรวจ

| Exercise | ผ่านเมื่อ |
| --- | --- |
| 1 | ≥ 10 CQ ที่ชัดเจน, glossary ครบทุก concept และ relation |
| 2 | ประเมิน ≥ 5 vocabulary ตามเกณฑ์ 7 ข้อ พร้อมสรุปแนะนำ/ไม่แนะนำ |
| 3 | mapping table ครบทุกรายการ + ระบุทางเลือกที่ไม่เลือกและเหตุผล |
| 4 | ontology parse ผ่าน, reuse ratio ≥ 60%, ทุก term ที่สร้างเองมี alignment |
| 5 | HTTP request ≤ ⌈N/25⌉, จัดการ ambiguous ถูกต้อง, ไม่ใช้ `owl:sameAs` มั่ว |
| 6 | SHACL ผ่าน, reasoner ผ่าน, CQ ตอบได้ ≥ 80%, มี HTML docs |

## Key Points

- Exercise 1 ตอกย้ำว่า **competency question มาก่อนการค้นหา vocabulary** เสมอ
- Exercise 2 ฝึก **ประเมิน vocabulary อย่างเป็นระบบ** ไม่ใช่เลือกตามชื่อที่คุ้นเคย
- Exercise 3 ฝึกสิ่งที่สำคัญที่สุด: **บันทึกเหตุผลของการตัดสินใจ** รวมถึงทางเลือกที่ไม่เลือก
- Exercise 4 วัด **reuse ratio** เป็นตัวเลข — ทำให้ประเมินคุณภาพการออกแบบได้
- Exercise 5 ฝึก **entity linking ที่รับผิดชอบ** — เลือก alignment property ตามระดับความมั่นใจ
- ⚠️ **ambiguous match ห้ามใช้ `owl:sameAs`** — ใช้ `rdfs:seeAlso` แล้วให้คนตรวจ
- Exercise 6 เชื่อมทุกอย่างเข้ากับ **validation pipeline** ที่จะขยายต่อใน [Chapter 10](../10-ontology-design/10.08-evaluation.md)
- เก็บ ontology และ mapping table ไว้ เพราะจะนำไปใช้ต่อใน Chapter 10 และ 12
