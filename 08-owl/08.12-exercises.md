แบบฝึกหัดชุดนี้ให้สร้าง **Family ontology** ที่ใช้ OWL construct ครบทุกกลุ่ม แล้วทดสอบด้วย reasoner

### Exercise 1: สร้าง Family ontology — class และ property

**โจทย์**

สร้างไฟล์ `family.ttl` (หรือ `family.py` ด้วย owlready2) ที่มี

**Class hierarchy**

```
Person
├── Man
└── Woman

Pet
├── Dog
└── Cat
```

**Disjointness ที่ต้องมี**

- `Man` กับ `Woman` disjoint
- `Person` กับ `Pet` disjoint
- `Dog` กับ `Cat` disjoint (ใช้ `owl:AllDisjointClasses`)
- `Person` แบ่งเป็น `Man` และ `Woman` พอดี (ใช้ `owl:disjointUnionOf`)

**Object properties พร้อม characteristics ที่ถูกต้อง**

| Property | Domain | Range | Characteristics ที่ต้องมี |
| --- | --- | --- | --- |
| `hasParent` | Person | Person | Asymmetric, Irreflexive |
| `hasChild` | Person | Person | inverse ของ `hasParent` |
| `hasMother` | Person | Woman | Functional, subPropertyOf `hasParent` |
| `hasFather` | Person | Man | Functional, subPropertyOf `hasParent` |
| `hasSibling` | Person | Person | Symmetric, Irreflexive |
| `hasBrother` | Person | Man | subPropertyOf `hasSibling` |
| `hasSister` | Person | Woman | subPropertyOf `hasSibling` |
| `marriedTo` | Person | Person | Symmetric, Irreflexive |
| `hasAncestor` | Person | Person | **Transitive** |
| `ownsPet` | Person | Pet | — |

**Data properties**

| Property | Range | Characteristics |
| --- | --- | --- |
| `nationalId` | `xsd:string` | Functional, InverseFunctional |
| `birthYear` | `xsd:integer` | Functional |
| `givenName` | `xsd:string` | — |

**คำถามที่ต้องตอบ**

1. ทำไม `hasAncestor` จึงเป็น Asymmetric ไม่ได้ ทั้งที่ความหมายควรจะเป็น
2. ถ้าประกาศ `hasParent rdfs:subPropertyOf hasAncestor` แล้ว `hasParent` ยังเป็น simple role อยู่ไหม
3. ทำไม `hasMother` จึงควรเป็น Functional แต่ `hasParent` ไม่ควร

**Expected output**

```bash
python -c "
from rdflib import Graph
from rdflib.namespace import OWL, RDF
g = Graph().parse('family.ttl', format='turtle')
classes = set(g.subjects(RDF.type, OWL.Class))
obj_props = set(g.subjects(RDF.type, OWL.ObjectProperty))
data_props = set(g.subjects(RDF.type, OWL.DatatypeProperty))
trans = set(g.subjects(RDF.type, OWL.TransitiveProperty))
symm = set(g.subjects(RDF.type, OWL.SymmetricProperty))
func = set(g.subjects(RDF.type, OWL.FunctionalProperty))
disj = len(list(g.subject_objects(OWL.disjointWith)))
print(f'classes           : {len(classes)}')
print(f'object properties : {len(obj_props)}')
print(f'data properties   : {len(data_props)}')
print(f'transitive        : {sorted(str(p).split(chr(35))[-1] for p in trans)}')
print(f'symmetric         : {sorted(str(p).split(chr(35))[-1] for p in symm)}')
print(f'functional        : {sorted(str(p).split(chr(35))[-1] for p in func)}')
print(f'disjointWith      : {disj}')
assert len(classes) >= 7 and len(obj_props) >= 10
print('PASS')
"
```

```
classes           : 7
object properties : 10
data properties   : 3
transitive        : ['hasAncestor']
symmetric         : ['hasSibling', 'marriedTo']
functional        : ['birthYear', 'hasFather', 'hasMother', 'nationalId']
disjointWith      : 2
PASS
```

### Exercise 2: เพิ่ม defined class ด้วย restriction

**โจทย์**

เพิ่ม **defined class อย่างน้อย 10 ตัว** โดยใช้ restriction ให้ครบทุกแบบ

| Class | นิยาม | Construct ที่ต้องใช้ |
| --- | --- | --- |
| `Parent` | Person ที่มีลูกอย่างน้อย 1 คน | `someValuesFrom` |
| `Mother` | Woman ที่เป็น Parent | `intersectionOf` |
| `Father` | Man ที่เป็น Parent | `intersectionOf` |
| `Grandparent` | Person ที่มีลูกที่เป็น Parent | nested `someValuesFrom` |
| `ChildlessPerson` | Person ที่ไม่มีลูกเลย | `maxCardinality 0` |
| `LargeFamily` | Person ที่มีลูก ≥ 3 คน | `minQualifiedCardinality` |
| `SonlessParent` | Parent ที่มีลูกแต่ไม่มีลูกชายเลย | `maxQualifiedCardinality 0` |
| `OnlyDaughtersParent` | Parent ที่มีลูกเฉพาะผู้หญิง | `someValuesFrom` + `allValuesFrom` |
| `MarriedPerson` | Person ที่แต่งงานแล้ว | `someValuesFrom` |
| `DogOwner` | Person ที่มีสุนัข | `someValuesFrom` |
| `PetLover` | Person ที่มีสัตว์เลี้ยง ≥ 2 ตัว | `minQualifiedCardinality` |
| `SelfMarriedPerson` | Person ที่แต่งงานกับตัวเอง | `hasSelf` — **ควร unsatisfiable** |

**คำถามที่ต้องตอบ**

1. ทำไม `OnlyDaughtersParent` จึงต้องมี `someValuesFrom` ด้วย ไม่ใช่แค่ `allValuesFrom`
2. `SelfMarriedPerson` ควร unsatisfiable เพราะอะไร
3. ถ้าเปลี่ยน `Parent` จาก `equivalentClass` เป็น `subClassOf` ผลจะต่างกันอย่างไร

**Expected output**

```
defined classes: 12
  Parent                   ≡ Person and (hasChild some Person)
  Mother                   ≡ Woman and Parent
  Father                   ≡ Man and Parent
  Grandparent              ≡ Person and (hasChild some Parent)
  ChildlessPerson          ≡ Person and (hasChild max 0)
  LargeFamily              ≡ Person and (hasChild min 3 Person)
  SonlessParent            ≡ Parent and (hasChild max 0 Man)
  OnlyDaughtersParent      ≡ Parent and (hasChild some Woman)
                                    and (hasChild only Woman)
  MarriedPerson            ≡ Person and (marriedTo some Person)
  DogOwner                 ≡ Person and (ownsPet some Dog)
  PetLover                 ≡ Person and (ownsPet min 2 Pet)
  SelfMarriedPerson        ≡ Person and (marriedTo Self)
```

### Exercise 3: สร้าง ABox และทำนายผล reasoning

**โจทย์**

สร้าง family tree ที่มีอย่างน้อย

- **10 คน** ครอบคลุม 3 รุ่น
- ครอบครัวหนึ่งที่มีลูก 3 คน (ทดสอบ `LargeFamily`)
- ครอบครัวหนึ่งที่มีลูกสาวอย่างเดียว 2 คน (ทดสอบ `OnlyDaughtersParent`)
- คนหนึ่งที่ไม่มีลูก (ทดสอบ `ChildlessPerson`)
- คู่แต่งงาน 2 คู่
- สัตว์เลี้ยง 3 ตัว โดยคนหนึ่งมี 2 ตัว
- `owl:AllDifferent` สำหรับทุกกลุ่ม

**ก่อนรัน reasoner** เขียน `prediction.md` ทำนาย:

| ต้องทำนาย | รูปแบบคำตอบ |
| --- | --- |
| ใครจะเป็น `Parent`, `Mother`, `Father` | รายชื่อ + เหตุผล |
| ใครจะเป็น `Grandparent` | รายชื่อ + trace การอนุมาน |
| ใครจะเป็น `LargeFamily` | รายชื่อ + ระบุว่าต้องมี `AllDifferent` หรือไม่ |
| ใครจะเป็น `ChildlessPerson` | **ระวัง OWA!** |
| ใครจะเป็น `OnlyDaughtersParent` | **ระวัง OWA!** |
| `hasAncestor` จะถูกอนุมานให้ใครบ้าง | จำนวน triple ที่คาดว่าจะเพิ่ม |
| `hasSibling` จะถูกอนุมานย้อนกลับให้ใครบ้าง | symmetric |

**Expected output**

```
====================================================================
  คำทำนาย vs ผลจริง
====================================================================
  Parent               ทำนาย: ['john','mary','peter','susan']   ได้จริง: [...]  ✅
  Mother               ทำนาย: ['mary','susan']                  ได้จริง: [...]  ✅
  Grandparent          ทำนาย: ['john','mary']                   ได้จริง: [...]  ✅
  LargeFamily          ทำนาย: ['john','mary']                   ได้จริง: []     ❌
  ChildlessPerson      ทำนาย: ['tom']                           ได้จริง: []     ❌
  OnlyDaughtersParent  ทำนาย: ['peter','susan']                 ได้จริง: []     ❌

  สาเหตุที่ไม่ตรง:
  1. LargeFamily ว่าง -> ลืม AllDifferent ให้ลูกทั้ง 3 คน
  2. ChildlessPerson ว่าง -> OWA: ไม่มี hasChild ≠ ไม่มีลูก
     ต้องเพิ่ม closure: tom a [ owl:onProperty hasChild ; owl:maxCardinality 0 ]
  3. OnlyDaughtersParent ว่าง -> OWA: allValuesFrom สรุปไม่ได้
     ต้องเพิ่ม closure: peter a [ owl:onProperty hasChild ;
                                  owl:allValuesFrom [ owl:oneOf ( ... ) ] ]

  หลังแก้ทั้ง 3 ข้อ: ✅ ตรงทั้งหมด
```

### Exercise 4: ทดสอบ inconsistency ทั้ง 4 กลไก

**โจทย์**

เพิ่มข้อมูลต่อไปนี้ **ทีละชุด** (ใช้ `World()` แยกทุกครั้ง) แล้วรัน reasoner

| ชุด | ข้อมูลที่เพิ่ม | กลไกที่คาดว่าจะจับได้ |
| --- | --- | --- |
| **A** | `fam:john a fam:Woman .` (john เป็น Man อยู่แล้ว) | ? |
| **B** | `fam:alice fam:hasMother fam:mary , fam:susan .` + AllDifferent | ? |
| **C** | `fam:john fam:hasSibling fam:john .` | ? |
| **D** | `fam:john fam:hasParent fam:tom . fam:tom fam:hasParent fam:john .` | ? |
| **E** | `fam:john fam:marriedTo fam:john .` | ? |
| **F** | `fam:alice fam:nationalId "ID-001" . fam:bob fam:nationalId "ID-001" .` + AllDifferent | ? |
| **G** | `fam:rex a fam:Dog , fam:Cat .` | ? |

**สำหรับแต่ละชุดให้**

1. ทำนายก่อนว่า consistent หรือไม่ และระบุกลไก
2. รัน reasoner ตรวจสอบ
3. เขียน **justification** — axiom ชุดที่เล็กที่สุดที่ทำให้เกิดปัญหา
4. เสนอทางแก้

**Expected output**

```
====================================================================
  ชุด A: john เป็นทั้ง Man และ Woman
====================================================================
  ทำนาย : INCONSISTENT (disjointWith)
  ผลจริง : ❌ INCONSISTENT
  Justification:
    1. fam:Man owl:disjointWith fam:Woman
    2. fam:john a fam:Man
    3. fam:john a fam:Woman
  ทางแก้: ลบข้อ 3

====================================================================
  ชุด B: alice มีแม่ 2 คนที่ต่างกัน
====================================================================

  ผลจริง : ❌ INCONSISTENT
  Justification:

    3. fam:alice fam:hasMother fam:susan
    4. AllDifferent(mary, susan)
  ทางแก้: ลบ AllDifferent -> reasoner จะสรุป mary sameAs susan แทน
          หรือแก้ข้อมูลให้มีแม่คนเดียว

```

พร้อมตารางสรุป:

| ชุด | Consistent? | กลไก |

| B | ❌ | `FunctionalProperty` + `AllDifferent` |
| C | ❌ | `IrreflexiveProperty` |
| D | ❌ | `AsymmetricProperty` |
| E | ❌ | `IrreflexiveProperty` |
| F | ❌ | `InverseFunctionalProperty` + `AllDifferent` |
| G | ❌ | `AllDisjointClasses` |

### Exercise 5: Property chain และ role hierarchy

**โจทย์**

เพิ่ม **property chain อย่างน้อย 6 ตัว** ลงใน Family ontology

| Property ใหม่ | Chain | ความหมาย |
| --- | --- | --- |
| `hasGrandparent` | `hasParent ∘ hasParent` | ปู่ย่าตายาย |
| `hasGrandmother` | `hasParent ∘ hasMother` | ย่า/ยาย |
| `hasUncle` | `hasParent ∘ hasBrother` | ลุง/อา |
| `hasAunt` | `hasParent ∘ hasSister` | ป้า/น้า |
| `hasNephew` | `hasSibling ∘ hasChild` (+ range Man) | หลานชาย |
| `hasCousin` | `hasParent ∘ hasSibling ∘ hasChild` | ลูกพี่ลูกน้อง |
| `hasStepMother` | `hasFather ∘ marriedTo` | แม่เลี้ยง |

**สิ่งที่ต้องตรวจสอบ**

1. ทุก chain ผ่าน **regularity condition** หรือไม่ — อธิบายด้วย strict partial order
2. ลอง**สร้าง chain ที่ผิดกฎ** แล้วดูว่า reasoner ตอบอย่างไร:
   ```turtle
   fam:r owl:propertyChainAxiom ( fam:s fam:r ) .
   fam:s owl:propertyChainAxiom ( fam:r fam:s ) .
   ```
3. ตรวจว่า property ไหนกลายเป็น **non-simple role** และมีผลอะไรตามมา

**Expected output**

```
====================================================================
  PROPERTY CHAIN INFERENCE
====================================================================
  hasGrandparent : 6 triples inferred
      alice -> john
      alice -> mary
      bob   -> john
      ...
  hasUncle       : 3 triples inferred
      alice -> peter
      ...
  hasCousin      : 4 triples inferred
      ...

====================================================================
  REGULARITY CHECK
====================================================================
  ✅ hasGrandparent : hasParent ≺ hasGrandparent    -- ผ่าน
  ✅ hasUncle       : hasParent, hasBrother ≺ hasUncle -- ผ่าน
  ❌ r / s ที่วนกลับ : reasoner ปฏิเสธ
     Error: "Non-simple role or regularity violation"

====================================================================
  SIMPLE ROLE CHECK
====================================================================
  simple roles      : hasParent, hasMother, hasFather, hasSibling,
                      hasBrother, hasSister, marriedTo, ownsPet
  non-simple roles  : hasAncestor (transitive),
                      hasGrandparent, hasUncle, hasAunt,
                      hasNephew, hasCousin, hasStepMother (chains)

  ผลตามมา: non-simple role ใช้กับ cardinality/functional/
           asymmetric/irreflexive/disjoint/hasSelf ไม่ได้
```

### Exercise 6 (โบนัส): เปรียบเทียบ OWL กับ SHACL

**โจทย์**

สำหรับข้อกำหนดต่อไปนี้ ให้เขียน **ทั้งแบบ OWL และแบบ SHACL** แล้วเปรียบเทียบผล

| # | ข้อกำหนด |
| --- | --- |
| 1 | "ทุก Person ต้องมี `nationalId` พอดี 1 ค่า" |
| 2 | "`nationalId` ต้องตรง pattern `^ID-[0-9]{3}$`" |
| 3 | "`birthYear` ต้องอยู่ระหว่าง 1900 ถึง 2025" |
| 4 | "Person ห้ามมี property นอกเหนือจากที่กำหนด" |
| 5 | "ทุก Parent ต้องมี `hasChild` อย่างน้อย 1" |

**สิ่งที่ต้องรายงาน**

| # | OWL เขียนได้ไหม | SHACL เขียนได้ไหม | OWL จับ error ได้ไหม | SHACL จับ error ได้ไหม |
| --- | :---: | :---: | :---: | :---: |
| 1 | ✅ `cardinality 1` | ✅ `sh:minCount 1 ; sh:maxCount 1` | ❌ (OWA) | ✅ |
| 2 | ⚠️ datatype restriction | ✅ `sh:pattern` | ⚠️ จำกัด | ✅ |
| 3 | ✅ `withRestrictions` | ✅ `sh:minInclusive` | ⚠️ | ✅ |
| 4 | ❌ | ✅ `sh:closed` | — | ✅ |
| 5 | ✅ `minCardinality 1` | ✅ `sh:minCount 1` | ❌ (OWA) | ✅ |

พร้อมสร้างข้อมูลที่ผิดจริง แล้วแสดงว่า:

```
====================================================================
  ทดสอบกับข้อมูลที่ผิด
====================================================================
  fam:tom a fam:Person .          # ไม่มี nationalId
  fam:jane fam:nationalId "XYZ" . # ผิด pattern
  fam:kim fam:birthYear 3000 .    # เกินช่วง

  OWL (HermiT):
    ✅ consistent — ไม่รายงานอะไร
    เพราะ OWA: "tom ต้องมี nationalId อยู่ที่ไหนสักแห่ง"

  SHACL (pySHACL):
    ❌ 3 violations
       Focus Node: fam:tom   | Path: nationalId | MinCount
       Focus Node: fam:jane  | Path: nationalId | Pattern
       Focus Node: fam:kim   | Path: birthYear  | MaxInclusive
```

พร้อมย่อหน้าสรุป 3–5 บรรทัดว่า **เมื่อไหร่ควรใช้ OWL และเมื่อไหร่ควรใช้ SHACL**

## Key Points

- Exercise 1–2 ฝึกใช้ **OWL construct ครบทุกกลุ่ม** ในโดเมนเดียวที่ต่อเนื่องกัน
- Exercise 3 ตอกย้ำสามกับดักหลัก: **`AllDifferent` ที่ลืม**, **`maxCardinality 0` ภายใต้ OWA**, **`allValuesFrom` ที่ต้องมี closure**
- Exercise 4 ครอบคลุม **กลไก inconsistency ทั้งหมด** — เป็นทักษะ debug ontology ที่สำคัญที่สุด
- Exercise 5 ฝึก **property chain** และเข้าใจ **regularity condition** กับ **simple role**
- Exercise 6 แสดงด้วยผลรันจริงว่า **OWL อนุมาน ส่วน SHACL ตรวจสอบ** — คนละหน้าที่กัน
- เก็บ `family.ttl` ไว้ เพราะจะนำไปใช้ต่อใน [Chapter 11](../11-swrl/11.12-exercises.md) สำหรับเขียน SWRL rule
