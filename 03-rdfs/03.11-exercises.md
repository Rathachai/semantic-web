### Exercise 1: สร้าง RDFS schema ของมหาวิทยาลัย

**โจทย์**

เขียนไฟล์ `university-tbox.ttl` ที่มี schema ตามข้อกำหนดนี้

**Class hierarchy ที่ต้องมี**

```
Agent
├── Person
│   ├── Student
│   │   └── GraduateStudent   (เป็น Researcher ด้วย)
│   ├── Staff
│   │   ├── Professor
│   │   └── AdminStaff
│   └── Researcher
└── Organization
    ├── University
    ├── Faculty
    └── Department
Course
Publication
```

**Property ที่ต้องมี**

| Property | Domain | Range | Sub-property ของ |
| --- | --- | --- | --- |
| `ex:involvedIn` | `ex:Person` | `ex:Course` | — |
| `ex:enrolledIn` | `ex:Student` | `ex:Course` | `ex:involvedIn` |
| `ex:teaches` | `ex:Professor` | `ex:Course` | `ex:involvedIn` |
| `ex:memberOf` | `ex:Person` | `ex:Organization` | — |
| `ex:partOf` | `ex:Organization` | `ex:Organization` | — |
| `ex:authorOf` | `ex:Researcher` | `ex:Publication` | — |
| `ex:credits` | `ex:Course` | `xsd:integer` | — |
| `ex:courseCode` | `ex:Course` | `xsd:string` | — |

**ข้อกำหนดเพิ่มเติม**

- ทุก class และทุก property ต้องมี `rdfs:label`@en และ `rdfs:comment`@en
- `rdfs:comment` ต้องบอก **ขอบเขต** และ **กรณีที่ไม่ใช้** อย่างน้อย 3 term
- ต้องมี ontology header พร้อม `dcterms:title`, `dcterms:created`, `owl:versionInfo`
- ทุก term ต้องมี `rdfs:isDefinedBy` ชี้กลับไปที่ ontology

**Expected output**

```bash
python -c "
from rdflib import Graph
from rdflib.namespace import RDF, RDFS
g = Graph().parse('university-tbox.ttl', format='turtle')
classes = set(g.subjects(RDF.type, RDFS.Class))
props   = set(g.subjects(RDF.type, RDF.Property))
no_label   = [t for t in classes|props if not list(g.objects(t, RDFS.label))]
no_comment = [t for t in classes|props if not list(g.objects(t, RDFS.comment))]
print(f'triples : {len(g)}')
print(f'classes : {len(classes)}')
print(f'props   : {len(props)}')
print(f'ขาด label   : {len(no_label)}')
print(f'ขาด comment : {len(no_comment)}')
assert len(classes) >= 12 and len(props) >= 8
assert not no_label and not no_comment
print('PASS')
"
```

```
triples : 118
classes : 12
props   : 8
ขาด label   : 0
ขาด comment : 0
PASS
```

### Exercise 2: เพิ่ม instance และทำนายผล reasoning ก่อนรัน

**โจทย์**

1. เขียนไฟล์ `university-abox.ttl` ที่มี instance อย่างน้อย 15 ตัว:
   - นักศึกษา 4 คน (มี graduate student อย่างน้อย 1)
   - อาจารย์ 2 คน
   - รายวิชา 4 วิชา — **ห้ามประกาศ `rdf:type` ให้รายวิชาเลย**
   - หน่วยงาน 3 ระดับ (University → Faculty → Department) เชื่อมด้วย `ex:partOf`
   - ผลงานตีพิมพ์ 2 ชิ้น

2. **ก่อนรัน reasoner** ให้เขียนคำทำนายลงไฟล์ `prediction.md` ว่าจะได้ inferred triple อะไรบ้าง
   ระบุกฎกำกับทุกข้อ (rdfs2/rdfs3/rdfs5/rdfs7/rdfs9/rdfs11)

3. รัน reasoner แล้วเทียบกับคำทำนาย

**Expected output**

ไฟล์ `prediction.md` มีรูปแบบ:

```markdown
| # | Inferred triple | กฎ | เหตุผล |
|---|---|---|---|
| 1 | ex:cs101 a ex:Course | rdfs3 | range ของ ex:enrolledIn |
| 2 | ex:alice a ex:Person | rdfs9 | Student ⊑ Person |
| 3 | ex:alice a ex:Agent | rdfs9 | Person ⊑ Agent (ผ่าน transitivity) |
| 4 | ex:alice ex:involvedIn ex:cs101 | rdfs7 | enrolledIn ⊑ involvedIn |
| ... | | | |
```

และผลการรัน:

```
คำทำนาย    : 34 triples
ได้จริง     : 36 triples
ทำนายถูก   : 33
ทำนายผิด   : 1
ตกหล่น     : 3
```

พร้อมย่อหน้าอธิบายว่า **ทำไมจึงตกหล่น** และ **ทำไมทำนายผิด**

### Exercise 3: ลิสต์ inferred triple ทั้งหมดพร้อมระบุกฎ

**โจทย์**

เขียนสคริปต์ `analyze_inference.py` ที่:

1. โหลด `university-tbox.ttl` + `university-abox.ttl` เข้า graph เดียวกัน
2. เก็บ asserted set ไว้ก่อน
3. รัน `owlrl.DeductiveClosure(owlrl.RDFS_Semantics).expand(g)`
4. คำนวณ inferred = closure − asserted
5. **แยกกลุ่ม** inferred ตามกฎที่น่าจะสร้างมัน:
   - `rdf:type` ที่ subject เป็น instance และ object เป็น class ที่ประกาศ subClassOf → **rdfs9**
   - `rdf:type` ที่ตรงกับ domain ของ property ที่ subject ใช้ → **rdfs2**
   - `rdf:type` ที่ตรงกับ range ของ property ที่ object ถูกใช้ → **rdfs3**
   - `rdfs:subClassOf` ที่ไม่ได้เขียนไว้ → **rdfs11**
   - `rdfs:subPropertyOf` ที่ไม่ได้เขียนไว้ → **rdfs5**
   - triple ที่มี predicate เป็น superproperty → **rdfs7**
   - ที่เหลือ → **noise** (rdfs1/4/6/8/10/12/13)
6. พิมพ์สรุปเป็นตารางและรายละเอียดแต่ละกลุ่ม

**Expected output**

```
====================================================================
  สรุปตามกฎ
====================================================================
  rdfs2  (domain)         :   9 triples
  rdfs3  (range)          :   6 triples
  rdfs7  (subProperty)    :   7 triples
  rdfs9  (subClass type)  :  18 triples
  rdfs5  (subProp trans)  :   2 triples
  rdfs11 (subClass trans) :  14 triples
  noise  (axiomatic)      : 121 triples
  --------------------------------------
  รวม inferred            : 177 triples
  มีความหมายจริง          :  56 triples (31.6%)

====================================================================
  rdfs9 — type propagation
====================================================================
  ex:alice      a ex:Person       <- ex:Student ⊑ ex:Person
  ex:alice      a ex:Agent        <- ex:Person ⊑ ex:Agent
  ex:alice      a ex:Researcher   <- ex:GraduateStudent ⊑ ex:Researcher
  ...
```

### Exercise 4: ตรวจจับ inference ที่ผิดพลาดจาก `rdfs:domain`

**โจทย์**

จาก schema ใน Exercise 1 ให้เพิ่มข้อมูลต่อไปนี้ ซึ่ง "ดูสมเหตุสมผล" แต่ทำให้เกิดการอนุมานที่ผิด

```turtle
@prefix ex: <http://example.org/university#> .

# TA (นักศึกษาช่วยสอน) ที่เป็น subproperty ของ teaches
ex:assists rdfs:subPropertyOf ex:teaches .

ex:bob a ex:Student ;
       ex:assists ex:cs101 .

# ห้องเรียนที่ "ใช้" ในรายวิชา
ex:room404 a ex:Room ;
           ex:involvedIn ex:cs101 .
```

**ให้ทำ**

1. รัน reasoner แล้วระบุ **triple ที่ผิดความหมาย** ทั้งหมด อธิบายว่ามาจากกฎข้อไหนและเพราะอะไร
2. เสนอ **ทางแก้อย่างน้อย 3 แนวทาง** พร้อมข้อดีข้อเสียของแต่ละแนวทาง:
   - แนวทาง A: ปรับ schema (ถอด/ขยาย domain)
   - แนวทาง B: ปรับ property hierarchy
   - แนวทาง C: ใช้ SHACL ตรวจแทนที่จะพึ่ง RDFS
3. เลือกทางแก้หนึ่งทาง implement แล้วพิสูจน์ว่า triple ที่ผิดหายไป

**Expected output**

```
====================================================================
  Inferred triples ที่ผิดความหมาย
====================================================================
  ex:bob     a ex:Professor    <- rdfs2 (domain ของ ex:teaches)
                                  ผิด: bob เป็นนักศึกษา ไม่ใช่อาจารย์
  ex:bob     a ex:Staff        <- rdfs9 (Professor ⊑ Staff)
  ex:room404 a ex:Person       <- rdfs2 (domain ของ ex:involvedIn)
                                  ผิด: ห้องเรียนไม่ใช่คน
  ex:room404 a ex:Agent        <- rdfs9 (Person ⊑ Agent)

  รวม 4 triples ที่ผิด

====================================================================
  หลังใช้ทางแก้ B (แยก ex:assists ออกจาก ex:teaches)
====================================================================
  triple ที่ผิด: 2 triples  (เหลือเฉพาะกรณี room404)

====================================================================
  หลังใช้ทางแก้ A + B
====================================================================
  triple ที่ผิด: 0 triples  ✅
```

### Exercise 5: อ่าน vocabulary จริงและ map เข้ากับ schema ของคุณ

**โจทย์**

1. โหลด **FOAF** จาก `http://xmlns.com/foaf/0.1/` และ **Dublin Core Terms** จาก `http://purl.org/dc/terms/`
   มาเป็น rdflib Graph
2. พิมพ์รายการ class และ property ของแต่ละ vocabulary พร้อม `rdfs:domain`/`rdfs:range`
3. หา **term ใน FOAF/dcterms ที่ตรงกับ term ในschema ของคุณ** อย่างน้อย 6 คู่
4. เขียนไฟล์ `alignment.ttl` ที่ใช้ `rdfs:subClassOf` และ `rdfs:subPropertyOf` เชื่อม schema ของคุณเข้ากับมาตรฐาน
5. รัน reasoner แล้วพิสูจน์ว่า query ด้วย **term มาตรฐาน** ได้ข้อมูลของคุณกลับมา

**Expected output**

ไฟล์ `alignment.ttl`:

```turtle
@prefix ex:      <http://example.org/university#> .
@prefix rdfs:    <http://www.w3.org/2000/01/rdf-schema#> .
@prefix foaf:    <http://xmlns.com/foaf/0.1/> .
@prefix dcterms: <http://purl.org/dc/terms/> .

ex:Person       rdfs:subClassOf    foaf:Person .
ex:Organization rdfs:subClassOf    foaf:Organization .
ex:University   rdfs:subClassOf    foaf:Organization .
ex:memberOf     rdfs:subPropertyOf foaf:member .
ex:authorOf     rdfs:subPropertyOf foaf:made .
ex:courseCode   rdfs:subPropertyOf dcterms:identifier .
```

ผลการทดสอบ:

```sparql
PREFIX foaf: <http://xmlns.com/foaf/0.1/>
SELECT ?p WHERE { ?p a foaf:Person . }
```

```
ก่อน alignment : 0 ผลลัพธ์
หลัง alignment : 6 ผลลัพธ์
  ex:alice, ex:bob, ex:carol, ex:dave, ex:profSmith, ex:profJones
```

พร้อมตารางสรุป mapping:

| Term ของเรา | Term มาตรฐาน | ความสัมพันธ์ | เหตุผล |
| --- | --- | --- | --- |
| `ex:Person` | `foaf:Person` | `rdfs:subClassOf` | คนของเราคือคนตามนิยาม FOAF ทุกกรณี |
| `ex:memberOf` | `foaf:member` | ⚠️ ทิศทางกลับกัน | `foaf:member` มี domain เป็น Group — ต้องระวัง |
| … | | | |

## Key Points

- Exercise 1 ฝึกสร้าง schema ที่มี **annotation ครบถ้วน** ซึ่งเป็นมาตรฐานขั้นต่ำของ ontology ที่ใช้ได้จริง
- Exercise 2 ฝึก **ทำนายผล inference ก่อนรัน** — ทักษะที่ทำให้เข้าใจกฎจริง ไม่ใช่แค่กดปุ่มรัน
- Exercise 3 ฝึกเชื่อม **inferred triple กลับไปหากฎที่สร้างมัน** ซึ่งจำเป็นตอน debug ontology
- Exercise 4 แสดงอันตรายที่แท้จริงของ `rdfs:domain` — และว่ามีทางแก้หลายแนวทางที่แลกกันคนละแบบ
- Exercise 5 ฝึก **vocabulary alignment** ซึ่งเป็นทักษะหลักที่จะใช้ต่อใน [Chapter 09](../09-well-known-ontologies/09.09-reusing-ontologies.md)
- เก็บ `university-tbox.ttl` และ `university-abox.ttl` ไว้ เพราะจะถูกนำไปขยายเป็น OWL ใน [Chapter 05](../05-knowledge-management/05.09-python-kb.md)
